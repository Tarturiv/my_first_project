# Ответы на вопросы для самоконтроля

## 1. В чем разница между временной сложностью O(n) и O(n²)?
O(n) — линейная сложность: время выполнения растёт пропорционально размеру входных данных (например, поиск максимума в массиве `findMax`). O(n²) — квадратичная: время растёт как квадрат размера данных (например, пузырьковая сортировка `bubbleSort` с двумя вложенными циклами). При увеличении n в 10 раз O(n) замедлится в 10 раз, а O(n²) — в 100 раз.

## 2. Как работает бинарный поиск и почему его сложность O(log n)?
Бинарный поиск работает только на отсортированном массиве. На каждом шаге он сравнивает целевой элемент со средним элементом массива и отбрасывает половину, в которой элемента точно нет. Так как на каждом шаге область поиска уменьшается вдвое, количество шагов равно log₂(n). Например, для 1 000 000 элементов нужно около 20 сравнений.

## 3. Преимущества и недостатки пузырьковой сортировки
**Преимущества:** простота реализации, понятность, не требует дополнительной памяти (in-place), стабильная сортировка.  
**Недостатки:** низкая эффективность O(n²), плохо масштабируется на больших массивах. Для больших данных лучше использовать быструю сортировку (QuickSort) или сортировку слиянием (MergeSort) со сложностью O(n log n).

## 4. Как оптимизировать проверку на простое число для больших чисел?
- Проверять делители только до √n, а не до n.
- Пропускать чётные числа после проверки деления на 2 (шаг 2).
- Использовать вероятностные тесты (тест Миллера — Рабина) для очень больших чисел.
- Применять решето Эратосфена, если нужно проверить много чисел в диапазоне.

## 5. Разница между рекурсивной и итеративной реализацией Фибоначчи
Рекурсивная реализация проста, но имеет экспоненциальную сложность O(2ⁿ) без мемоизации и риск переполнения стека. Итеративная реализация использует цикл и имеет сложность O(n) по времени и O(1) по памяти (если не хранить весь массив). Для больших n итеративный подход предпочтительнее.

## 6. Какие методы отладки использовались?
`console.log()` для вывода промежуточных значений, встроенные инструменты разработчика (Breakpoints, Watch, Call Stack), юнит-тесты с функцией `runTest` для автоматической проверки результатов, а также сравнение с ожидаемыми значениями.

## 7. Как работает алгоритм Евклида для НОД?
Алгоритм основан на свойстве: НОД(a, b) = НОД(b, a mod b). Повторяем замену `[a, b] = [b, a % b]`, пока b не станет равным 0. Тогда a — искомый НОД. Эффективен, потому что остаток быстро уменьшается, а сложность составляет O(log(min(a, b))).

## 8. Какие edge cases нужно учитывать при работе с массивами?
Пустой массив, массив из одного элемента, массив с одинаковыми элементами, отрицательные числа, `null`/`undefined`, очень большие массивы, неотсортированный массив для бинарного поиска, массив с `NaN` или нечисловыми значениями.

## 9. Как улучшить функцию удаления дубликатов для больших массивов?
Использовать `Set` — это даёт O(n) по времени. Для очень больших массивов можно применять хеш-таблицы или сортировку с последующим проходом (O(n log n)), если важна память. Также можно использовать `filter` с `indexOf`, но это O(n²) и неэффективно.

## 10. Какие принципы чистого кода применены?
Понятные имена функций и переменных, единая ответственность каждой функции, комментарии о сложности, обработка edge cases, отсутствие магических чисел, повторное использование кода, читаемое форматирование и отступы.
