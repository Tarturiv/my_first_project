1. Три основные области работы с файлами в Git:

    Рабочая папка (Working Directory) — текущие файлы на диске, с которыми ты работаешь.
    Индекс (Staging Area) — промежуточная область, куда попадают файлы после git add, готовые к коммиту.
    Репозиторий (Repository) — хранилище закоммиченных версий файлов (история).

2. Что происходит при выполнении команд:

    git add — добавляет изменения из рабочей папки в индекс (подготавливает к коммиту).
    git commit — фиксирует изменения из индекса в репозиторий, создавая новую версию.
    git push — отправляет закоммиченные изменения в удалённый репозиторий.

3. Почему важно писать информативные сообщения к коммитам:
Чтобы понимать, что и зачем было изменено, при просмотре истории. Это помогает в командной работе и при откате изменений. Сообщения типа "исправление" или "update" не несут полезной информации.

4. Чем отличается git add имя_файла от git add .:

    git add имя_файла — добавляет только указанный файл.
    git add . — добавляет все изменения в текущей папке и подпапках.
    Первый вариант лучше, когда нужно закоммитить только конкретные файлы; второй — когда нужно добавить всё сразу.

5. Что показывает git status:
Показывает состояние рабочей папки и индекса: какие файлы изменены, какие добавлены в индекс, какие не отслеживаются. Вывод меняется на разных этапах: до git add файлы в разделе "Changes not staged", после git add — в "Changes to be committed".

6. Для чего нужна git remote add origin URL:
Связывает локальный репозиторий с удалённым. Слово "origin" — это стандартное имя (псевдоним) для удалённого репозитория, к которому можно обращаться вместо полного URL.

7. Зачем нужен флаг -u в git push -u origin main:
Флаг -u (или --set-upstream) устанавливает связь между локальной веткой main и удалённой origin/main. После этого можно писать просто git push без указания удалённого репозитория и ветки.

8. Что такое ветка по умолчанию:
Ветка, которая создаётся при инициализации репозитория. Раньше Git создавал master, сейчас по умолчанию — main. Это важно, потому что GitHub и другие сервисы используют main как основную ветку, и при пуше нужно указывать правильное имя.

9. Как просмотреть историю коммитов:

git log
Показывает: хеш коммита, автора, дату, сообщение коммита. Для краткого вида — git log --oneline.

10. Что произойдёт, если сделать изменения, но не выполнить git add перед git commit:
Изменения не попадут в коммит. Git закоммитит только то, что было в индексе. Изменённые файлы останутся в рабочей папке как "not staged".

Сохрани файл и выполни коммит:
git add answers.txt
git commit -m "Добавлены ответы на вопросы для самоконтроля"
git push
