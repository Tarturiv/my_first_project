1.	Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?
- required — поле обязательно для заполнения.
- minlength / maxlength — минимальная/максимальная длина текста.
- mi` / max — минимальное/максимальное значение для чисел и дат.
- type (email, tel, url, number, date и др.) — проверка формата данных.
- patter` — регулярное выражение для проверки значения.
- step — шаг изменения числового значения.
- novalidate (на форме) — отключает встроенную браузерную валидацию.

2.	В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?
novalidate отключает встроенную браузерную валидацию (подсказки, блокировку отправки),
но поля остаются валидируемыми через checkValidity() и CSS-псевдоклассы :valid/:invalid.
Отключение валидации через JS (например, удаление атрибутов required) полностью убирает ограничения.
novalidate используется, когда нужна своя кастомная валидация с собственными сообщениями, но при этом сохраняется доступ к API валидации.

3.	Как правильно связать <label> с полем ввода и почему это важно для доступности?
Связь осуществляется через атрибут `for` у `<label>`, значение которого совпадает с `id` поля ввода:

<label for="email">Email</label>
<input type="email" id="email" name="email">

Это важно, потому что:
    Клик по метке фокусирует поле (удобство).
    Скринридеры озвучивают название поля.
    Увеличивается область клика для мобильных устройств.
    Соответствует стандартам WCAG.

Также можно оборачивать input внутрь label, но вариант с for/id предпочтительнее.

4.	Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?
  email — email-адреса (встроенная проверка формата).
  tel — телефоны (клавиатура с цифрами на мобильных).
  password — пароли (скрытие символов).
  number — числовые значения.
  date — даты (встроенный календарь).
  url — ссылки.
  search — поисковые запросы.
  checkbox / radio — выбор из вариантов.
  file — загрузка файлов.

5.	Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?
pattern принимает регулярное выражение (без якорей ^/$ — они подставляются автоматически).
Значение считается валидным, если целиком соответствует шаблону.
Используется для проверки специфичных форматов: телефон, почтовый индекс, номер карты, пароль с требованиями и т.д.
Не следует использовать для проверки email (есть type="email") и сложных случаев, где нужна серверная валидация.

6.	Какие события JavaScript используются для реализации валидации в реальном времени и почему?
    input – срабатывает при каждом изменении значения (мгновенная обратная связь, сброс ошибок).
    blur – срабатывает при потере фокуса (проверка после заполнения, не раздражает пользователя).
    change – для select, checkbox, radio.
    submit – финальная проверка перед отправкой.
Использование blur + input – оптимальный баланс: ошибки показываются после того, как пользователь закончил ввод, и исчезают при исправлении.

7.	Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?
Использовать aria-live="polite" или role="alert" на контейнере ошибки.
Связывать поле с сообщением через aria-describedby.
Устанавливать aria-invalid="true" на невалидное поле.
Не полагаться только на цвет – добавлять текст.
Перемещать фокус на первое поле с ошибкой при неудачной отправке.

8.	В чем преимущества использования fieldset и legend для группировки полей формы?
Семантическая группировка связанных полей.
Скринридеры озвучивают legend как заголовок группы.
Улучшает навигацию и понимание структуры формы.
Стилизация группы как единого блока.
Обязательно для групп радиокнопок (одно name – один fieldset).

9.	Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?
    Отключить встроенную валидацию через novalidate.
    Добавить обработчик input на оба поля пароля.
    Сравнивать значения и показывать/скрывать сообщение об ошибке.
    Использовать setCustomValidity() для интеграции с API валидации:
if (password.value !== confirmPassword.value) {
    confirmPassword.setCustomValidity('Пароли не совпадают');
} else {
    confirmPassword.setCustomValidity('');
}

    Проверять при submit и блокировать отправку при несовпадении.

10.	Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?
Псевдоклассы :valid / :invalid – автоматическая стилизация.
:required / :optional – стилизация обязательных полей.
:focus / :focus-visible – стилизация фокуса.
:placeholder-shown – определение пустого поля.
Комбинации: input:invalid:not(:focus):not(:placeholder-shown) – показывать ошибку только после ввода.
Классы .error, добавляемые через JS, для кастомной стилизации.
@keyframes для анимации (например, shake при ошибке).
