\# Ответы на вопросы для самоконтроля



\## 1. Function Declaration vs Function Expression и hoisting



\*\*Function Declaration\*\* (`function foo() {}`) поднимается (hoisted) целиком — её можно вызвать до объявления в коде. \*\*Function Expression\*\* (`const foo = function() {}`) hoisting не подвержена: переменная поднимается, но остаётся `undefined` до присваивания, поэтому вызов до строки объявления вызовет `TypeError: foo is not a function`.



```js

fooDecl(); // ✅ работает

function fooDecl() {}



fooExpr(); // ❌ TypeError

const fooExpr = function () {};


```


2\\\\. Rest parameters vs arguments

...args — настоящий массив (Array.isArray(args) === true), можно использовать методы массивов.



arguments — array-like объект, не массив; у него нет map, filter и т.д. Работает только в обычных функциях (в стрелочных недоступен).



rest собирает только оставшиеся параметры (function f(a, ...rest)), arguments содержит все аргументы.



arguments содержит все аргументы, включая не объявленные в сигнатуре; rest — тоже, но более явно и безопасно.



3\\\\. Замыкание и лексическая область видимости

Замыкание — это функция, которая запоминает лексическое окружение, в котором была создана, даже после выхода из этого окружения. Это возможно благодаря лексической области видимости: функция ищет переменные там, где она определена, а не там, где вызвана. Классический пример — secretMessage: возвращённая функция «помнит» password и message.



4\\\\. Рекурсия vs итерация

Рекурсия — элегантна для древовидных структур (деревья, графы), задач «разделяй и властвуй» (быстрая сортировка, обход директорий). Минусы: риск переполнения стека, накладные расходы на вызовы.



Итерация — эффективнее по памяти и скорости, лучше для линейных задач (сумма массива, поиск).



Правило: если задача естественно рекурсивна — рекурсия; иначе — итерация. В JS рекурсию часто заменяют циклом или хвостовой рекурсией (которая, впрочем, не оптимизируется автоматически).



5\\\\. Функции высшего порядка

Функция высшего порядка — та, что принимает функцию как аргумент или возвращает функцию. Встроенные методы массивов: map, filter, reduce, forEach, sort, some, every, find, flatMap. В работе реализованы myMap, myFilter, myReduce, compose, curry, debounce, throttle.



6\\\\. Каррирование

Каррирование — преобразование функции от N аргументов в цепочку функций от одного аргумента: f(a,b,c) → f(a)(b)(c). Преимущества:



частичное применение (partial application) — фиксируем часть аргументов;



переиспользование и композиция;



удобство в функциональном стиле (const add5 = curry(add)(5)).



7\\\\. Мемоизация

Мемоизация — кэширование результатов функции по её аргументам. Эффективна для чистых функций с дорогими вычислениями и повторяющимися аргументами (рекурсивные алгоритмы, фибоначчи, парсинг). Не подходит для функций с побочными эффектами и для случаев, когда аргументы — сложные объекты (нужен стабильный ключ; в реализации используется JSON.stringify).



8\\\\. Debounce vs throttle

Debounce — откладывает вызов до тех пор, пока не пройдёт delay с момента последнего вызова. Идеален для поиска по вводу, автосохранения.



Throttle — гарантирует вызов не чаще, чем раз в interval, независимо от частоты событий. Идеален для scroll, resize, mousemove.



Debounce «ждёт тишины», throttle «пропускает с частотой».



9\\\\. Генераторы (function\\\\\\\*)

Функция-генератор возвращает итератор и может приостанавливаться на yield, возобновляясь по next(). Отличия от обычных функций:



не выполняются сразу, а возвращают объект-итератор;



могут возвращать несколько значений через yield;



поддерживают двусторонний обмен (next(value) передаёт значение внутрь);



удобны для ленивых последовательностей, асинхронного кода (async function\\\\\\\*), обхода структур.



10\\\\. Принципы ФП в работе

Чистые функции — sum, myMap, myFilter, myReduce не мутируют вход и не имеют побочных эффектов.



Функции высшего порядка — compose, curry, memoize.



Иммутабельность — myMap/myFilter возвращают новые массивы, не изменяя исходный.



Композиция — compose собирает сложное поведение из простых функций.



Замыкания — secretMessage, createValidator, debounce, throttle.



Преимущества: предсказуемость, тестируемость, переиспользование, лёгкая композиция, меньше багов из-за побочных эффектов.
